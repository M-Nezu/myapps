# 要件定義書: 地図マーキングアプリ esqmap (GAS Webアプリ版)

## 1. プロジェクト概要
本プロジェクトは、Google map を表示し、ユーザーがマップ上にカスタムマークを配置できるシングルページWebアプリケーション（SPA）を、Google Apps Script (GAS) Webアプリとして構築するものである。
バックエンドのデータベースとしてGoogleスプレッドシートを利用し、複数クライアントからの非同期的な読み書き・同時アクセスに耐えうる堅牢なデータ同期機構を備える。
使用クライアント環境は主にスマートフォン上のブラウザをターゲットとする。

## 2. システムアーキテクチャ
*   **フロントエンド:** HTML, CSS (Tailwind CSS), JavaScript (Vanilla), Leaflet.js
*   **バックエンド:** Google Apps Script (GAS)
*   **データベース:** Google スプレッドシート
*   **通信方式:** `google.script.run` を利用した非同期RPC通信

## 3. データベース設計 (Google スプレッドシート)
スプレッドシートの1番目のシート（シート名: `Marks` 等）をデータベースとして使用する。1行を1つのマークデータとして扱う。

### カラム定義 (1行目はヘッダー)
*   **A列 `id`:** マークのユニークID (文字列または数値) ※主キー
*   **B列 `title`:** マークのタイトル (文字列)
*   **C列 `memo`:** メモ内容 (文字列)
*   **D列 `shape`:** 形状ID (`small-circle`, `small-triangle`, または `house`)
*   **E列 `color`:** カラーコード (`#ffffff`, `#9ca3af`, `#111827`)
*   **F列 `lat`:** 緯度 (数値)
*   **G列 `lng`:** 経度 (数値)
*   **H列 `createdAt`:** 作成日時 (ISO 8601形式の文字列)
*   **I列 `updatedAt`:** 最終更新日時 (ISO 8601形式の文字列)

## 4. バックエンド (GAS) 要件
GASはHTMLをサーブする機能と、フロントエンドから呼ばれるAPIエンドポイント機能を提供する。

### 4.1 HTMLのサーブ
*   `doGet(e)` 関数を実装し、`HtmlService.createHtmlOutputFromFile('index')` を用いて、フロントエンドのHTMLをレンダリングして返す。

### 4.2 API関数 (`google.script.run` 経由で呼び出し)
複数クライアントからのアクセスを考慮し、適切に排他制御を行うこと。

#### ① `getAllMarks()`
*   **処理:** シート全体のデータを読み込み、JSONオブジェクトの配列としてフロントエンドに返す。
*   **用途:** クライアント起動時の初回データロード用。

#### ② `createMark(data)`
*   **処理:** 新規マークをシートの最終行に追加する。
*   **排他制御 (重要):** 
    *   `LockService.getScriptLock()` を使用し、排他ロックを取得する（タイムアウト設定: 10秒程度）。
    *   ロック取得後、現在の最大IDを取得してインクリメント、または `Utilities.getUuid()` 等を利用して重複しない `id` を払い出す。
    *   シートの `appendRow()` でデータを追加する。
    *   処理完了後にロックを解放し、払い出した `id` と作成済みデータをフロントエンドに返す。

#### ③ `updateMark(id, data)`
*   **処理:** 既存のマーク情報を更新する。
*   **同時実行の考慮 (重要):**
    *   行番号を固定でキャッシュして上書きするのではなく、呼び出し時に `TextFinder` (`sheet.createTextFinder(id).matchEntireCell(true)`) または全件スキャンを用いて、該当 `id` が存在する「現在の行番号」を動的に特定する。
    *   これにより、別のクライアントが別のマークを削除・追加して行がずれたり、同時に別のマークを更新したりしても、目的のIDの行だけを正確に更新（`getRange(row, 1, 1, numCols).setValues(...)`）できる。

#### ④ `deleteMark(id)`
*   **処理:** 指定された `id` のマークをシートから削除する。
*   **同時実行の考慮:** 更新と同様に `TextFinder` 等で現在の行番号を動的に検索し、`sheet.deleteRow(row)` を実行する。ロック処理（`ScriptLock`）を併用することが望ましい。

## 5. フロントエンド (HTML/JS) 要件

### 5.1 地図表示・操作UI
*   **地図エンジン:** Leaflet.js
*   **ベースマップ:** Google map タイルをタイルサーバへ直接リクエストする (プロトタイプ用。Google Maps Platform API は使用しない)。
    *   初期表示: Google map (標準)
    *   レイヤー切替: Google map (標準)、Google map (施設アイコン無し)、Google map (衛星写真)
    *   施設アイコン無しレイヤーはタイル取得URLに `apistyle=s.t%3A2%7Cp.v%3Aoff` を付与する。
*   **操作:** スワイプ、ドラッグによるスクロール。ピンチイン・アウトによるズーム。
*   **UI要素:**
    *   画面中央に固定の十字カーソル（赤色リング等）。
    *   上部に中央十字座標（緯度経度）をリアルタイム表示。
    *   地図の濃さ切替トグルボタン（Opacity 1.0 / 0.4）。左下のレイヤー選択ボタンの上に配置する。
    *   現在地に移動するボタン（Geolocation API使用）。右下の拡大縮小ボタンの上に配置する。
    *   「中央カーソル地点にマーク」ボタン（画面下部）。

### 5.2 マーク機能UI
*   **マークの見た目:**
    *   形状: 小さい丸 (`small-circle`)、頂点が上向きの小さな正三角形 (`small-triangle`)、五角形の単純な家形 (`house`) の3種。
    *   色: 白 (`#ffffff`)、灰 (`#9ca3af`)、黒 (`#111827`) の3種。
    *   縁取り: 青色 (`#2563eb` 相当)。
    *   タイトル表示: マークのすぐ右側に白縁取り（ドロップシャドウ）テキストで常時表示。「小丸」の場合は特にマークに近づける。
*   **マーク登録/編集モーダル:**
    *   入力項目: タイトル、形状選択、色選択、メモ。メモ欄は最後に配置する。
    *   「中央カーソル地点にマーク」押下で新規作成モーダル表示。
    *   マップ上の既存マーククリック時のポップアップ内「編集」ボタンで編集モーダル表示。
*   **一覧表示:**
    *   保存済みマークをリスト表示するドロワー（サイドパネル）。
    *   タイトルの昇順で表示する。連続する数字は数値として比較する自然順ソートとする（例: 地点2 → 地点10）。
    *   タイトルが同じ場合は色が薄い順（白 → 灰 → 黒）、色も同じ場合は形状順（家 → △ → 〇）で表示する。

### 5.3 状態管理と通信フロー
*   **ローカルストレージの廃止:** データの永続化先はすべてGAS側に寄せる。
*   **初期化フロー:**
    1. 画面ロード完了時にローディングUIを表示。
    2. `google.script.run.withSuccessHandler(initMap).getAllMarks()` を呼び出し。
    3. 取得したデータでマップ上にマークをレンダリングし、ローディングUIを消去。
*   **非同期更新 (Optimistic UI の推奨):**
    *   UIのレスポンスを良くするため、クライアント側で先にマークの描画やUI更新を行い、バックグラウンドで `google.script.run` を呼び出してGASと同期をとる（あるいはローディングスピナーを表示して完了を待つ）。
    *   新規作成時のIDは、GASでの作成完了レスポンス（SuccessHandler）を受け取ったタイミングでクライアントのオブジェクトとDOM（Leafletマーカーの参照）にバインドする。

## 6. AIエージェントへの実装指示
本要件定義に基づき、以下のファイルを出力すること。

1.  **`コード.gs`**: バックエンド処理を担うGASファイル。`doGet`, `getAllMarks`, `createMark`, `updateMark`, `deleteMark` を実装し、排他制御および行の動的検索ロジックを含めること。
2.  **`index.html`**: フロントエンドのHTML/CSS/JSを統合した1ファイル。GASのタグ (`<?= ... ?>`) は必要最小限とし、API通信は `google.script.run` で実装すること。
3.  claspを使ったデプロイ手順書
4.  その他GAS Webアプリとして必要なファイル
